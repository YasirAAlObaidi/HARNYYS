Connect WhatsApp to the app

This guide takes you from nothing to a working WhatsApp chat with the app, using Meta's free test phone number. You do not need to have used Meta's developer tools before. Follow the steps in order.

About 30 to 45 minutes Checked against Meta's documentation on 25 November 2026

How to read this guide

  • Each step says what to click, what you should see afterwards, and what to copy where.
  • Commands go into the Terminal app on the Mac. Each command has a Copy button.
  • Words highlighted in yellow inside a command, like THIS, are placeholders. Replace them with your own value.
  • Meta changes its screens often. A label may differ tag means the button or menu name came from a source that may be out of date. Look for the closest match.
  • A not verified tag marks a fact I could not confirm in Meta's current documentation.
  • Every step has a yellow If this goes wrong box. Open it when something does not match.
Keep these secret

The App Secret, the access token, the verify token, the model key and the database password work like passwords. They live in one file, deploy/.env, and nowhere else.

  • Never commit deploy/.env to git. Step 0 checks that git ignores it.
  • Never paste a secret into a chat, an email, a ticket or a screenshot.
  • If one leaks, replace it. Each step says how.

The big picture

WhatsApp cannot knock on your Mac's door directly. Meta needs a public web address to send each customer message to. A tunnel gives your Mac that address. The reply goes back out the other way, straight from the app to Meta.

A message comes in
Customer's phoneSends a WhatsApp message to the test number.
→
MetaCalls your webhook address and signs the call with your App Secret.
→
TunnelA public https address that forwards to your Mac.
→
The app, on your MacChecks the signature, saves the message, queues an answer.
The reply goes out
The app (worker)Asks the AI model for an answer.
→
MetaAccepts the reply because the app shows the access token.
→
Customer's phoneShows the reply.

What you need before you start

5 min
  • A Facebook account (a personal one is fine). Meta's developer tools log in with it.
  • A phone with WhatsApp installed, to receive test messages. A second phone is useful if two people will take part in the demo.
  • The Mac with the project, at /Users/yasir/HARNYYS, with Colima and Homebrew installed.
  • An OpenRouter account. It gives you the model key in step 6. Sign up at openrouter.ai now if you do not have one.
  • About 30 to 45 minutes.

The test phone number is free. Meta's documentation says test numbers need no payment method to send template messages. You do not need a credit card for this guide.

First, set up the secrets file. Every value you collect later goes straight into it, so nothing is left lying around.

  1. Open Terminal. Press Cmd + Space, type Terminal, press Return.
  2. Go to the project folder. 
    cd /Users/yasir/HARNYYS
  3. Create your secrets file from the template. The -n means it will not overwrite a file you already have. 
    cp -n deploy/.env.example deploy/.env
    You should seeNothing. The command prints no output when it works.
  4. Check that git ignores the file. 
    git check-ignore -v deploy/.env
    You should seeOne line ending in deploy/.env. If nothing prints, stop and ask for help before going on.
  5. Open the file in TextEdit and leave that window open for the rest of the guide. 
    open -e deploy/.env
    You should seeA text window with lines such as POSTGRES_PASSWORD= and WHATSAPP_APP_SECRET=, each followed by nothing. You will fill them in as you go. Save with Cmd + S each time.

Make a Meta developer account and a WhatsApp app

10 min

Meta calls what you are about to make an app. It is not a phone app. It is a settings area on Meta's side that holds your test number and your keys.

  1. In your web browser, open developers.facebook.com/apps and log in with your Facebook account.
  2. If Meta asks you to register as a developer, follow the prompts and accept the terms. Meta may ask you to confirm with a code.
    You should seeA page listing your apps, called the App Dashboard. It is empty if you have never made an app.
  3. Click Create App.
  4. Type an app name, for example Kahraman WhatsApp demo, and your email address. Click Next.
  5. When Meta asks what you want to do, choose Connect with customers through WhatsApp. Click Next.
  6. Under business portfolio, pick an existing one or create a new one. Click Next.

    A business portfolio is Meta's name for the company account that owns apps and phone numbers.

  7. Meta may list publishing requirements. The list can be empty. Click Next.
  8. Check the summary and click Create app. Enter your Facebook password if asked.
    You should seeA page headed Customize use case with Connect on WhatsApp and Quickstart.
  9. Click Start using the API.
    You should seeThe API Setup page. It also appears as API Setup in the left-hand list of that page.
  10. On API Setup, connect your app to a WhatsApp account. Choose an existing one from the dropdown, or click Create a WhatsApp Business account and follow the prompts.
    You should seeAn account ID shown on the API Setup page. Meta's current documents call it the Messaging account ID. Older screens call it the WhatsApp Business Account ID (WABA ID). It is the same thing.
  11. Find your test number. Under From, a test phone number should already be selected, and a Phone number ID is shown nearby. label may differ
    Copy this

    Copy the Phone number ID. It is a long number. It is not the phone number people dial. Paste it into deploy/.env:

    WHATSAPP_PHONE_NUMBER_ID= followed by the number, with no spaces and no quotes.

  12. Copy the account ID too, and paste it at the bottom of deploy/.env as a comment line. The app ignores comment lines. The ID is not secret, and you may need it in step 11 and when talking to Meta support. 
    # Messaging account (WABA) ID: PASTE_THE_ID_HERE
If this goes wrong
  • You do not see "Connect with customers through WhatsApp". Meta's screens vary by account. Pick the closest option that mentions WhatsApp. If you are offered a general Business app type instead, choose it, then add the WhatsApp product from the list of products and click Set up. not verified
  • The From dropdown has no test number. Meta documents that a test number is created for you once you finish the Get Started steps. Click Start using the API again, wait a minute, and reload the page. Do not add your own number here. That is for a real number, which is a separate job.
  • Meta asks to confirm your identity or turn on two-factor login. Do it. It is a normal Meta check.

Add your phone as a test recipient and send the first message

5 to 10 min

The test number can only message phones that you add to a list and confirm with a code. Meta shows the exact limit on screen. I expect it to be 5 phones. not verified

  1. On the API Setup page, find the section where you pick From and To for a message. It is named Send and receive messages on most screens. label may differ
  2. Make sure From shows your test number.
  3. Open the To dropdown and choose Manage phone number list. label may differ
  4. Choose to add a number. Pick the country, then type the phone number that has WhatsApp. Continue.
  5. Meta sends a confirmation code to that phone, by WhatsApp message. Type the code into Meta's page and confirm.
    You should seeThe number now appears in the To dropdown. A number that is added but not confirmed does not work.
  6. Repeat steps 2.4 and 2.5 for every phone that will take part in the demo, up to the limit.
  7. With your phone chosen under To, click Generate access token if the button is there. Accept any prompt. This is the short-lived token. You will not use it in the app. Step 4 explains why.
  8. Click Send message.
    You should seeWithin a few seconds, WhatsApp on that phone shows a new chat from the test number. The message is a short greeting. It is Meta's ready-made hello_world message.
  9. On the phone, open that chat and reply with Hi.

    A reply opens a 24-hour window in which the app may answer freely. It also gives you the chat you will use in step 10.

If this goes wrong

  • No code arrives. Check that the number has WhatsApp and that you chose the right country. Wait one minute and try again.
  • The greeting does not arrive. Check the number shows as confirmed in the list. Meta reports error 131030 when you message a number that is not on the list.

Get the App Secret

2 min

The App Secret is a password that only you and Meta know. Meta uses it to sign every call it makes to your webhook. The app uses it to check that signature, so it can tell real Meta calls from fakes.

  1. In the App Dashboard, open the left-hand menu and click App settings, then Basic. label may differ
  2. Find the line App secret and click Show. Enter your Facebook password if asked. label may differ
    You should seeA string of letters and digits instead of dots. The App ID above it is a different, public number. Do not copy that one.
  3. Copy this

    Paste the App secret into deploy/.env:

    WHATSAPP_APP_SECRET= followed by the secret, no spaces, no quotes. Save the file.

If this goes wrong
  • You cannot find App settings. Use the search box at the top of the dashboard, or look under your app's name in the left-hand menu.
  • Later, messages arrive but the app answers 401. The secret in .env does not match this one. Copy it again, with no extra space at the end.
  • You think the secret leaked. Meta lets you reset it on this same page. After a reset, paste the new one into .env and restart the app (step 7).
4

Make a permanent access token

10 min

The access token is the key the app shows Meta each time it sends a reply. The one on the API Setup page is a temporary token. Meta says it "expires quickly" and has to be regenerated every few hours. When it expires, the app still receives messages but every reply fails. For a demo that has to work on the day, make a permanent one. Meta calls it a system user token. It belongs to a robot user, not to you.

  1. Open business.facebook.com/settings in a new tab. This is Business settings.
  2. If Meta asks which business portfolio, choose the one you picked in step 1.
  3. In the left-hand menu, click Users, then System users. label may differ
  4. Click Add. In the window that opens, type a name such as yyai-whatsapp, set the role to Admin, and click Create system user.
    You should seeThe new system user in the list.
  5. Click the new system user's name, then click Assign assets.
  6. In the window that opens, choose the Apps tab and select your app. Turn on Manage app (listed under Full control). Click Assign assets.
  7. Click Assign assets again. Choose the WhatsApp accounts tab and select your WhatsApp account. Turn on Manage WhatsApp Business accounts (under Full control). Click Assign assets. label may differ
    You should seeBoth the app and the WhatsApp account listed for this system user with Full control. Meta says this can take a few minutes. Reload the page if you do not see it yet.
  8. Click Generate token.
  9. Choose your app. For expiry, choose Never if it is offered. If not, choose the longest option and put the date in your calendar. not verified
  10. In the permissions list, tick all three. Typing business in the search box helps you find them.
    • whatsapp_business_messaging
    • whatsapp_business_management
    • business_management
  11. Click Generate token.
    You should seeA very long string of letters and digits. Meta shows it once.
  12. Copy this

    Copy the token straight away. Paste it into deploy/.env:

    WHATSAPP_ACCESS_TOKEN= followed by the token, no spaces, no quotes. Save the file.

If this goes wrong
  • You lost the token before copying it. Click Generate token again. Make a new one. The old one keeps working until it expires, so revoke it if you are worried.
  • The permission names are missing from the list. The app has not been assigned to the system user yet. Wait a few minutes, reload, and check step 4.6.
  • The Add button is greyed out. Your Facebook account is not an admin of this business portfolio. Ask the person who owns it to do steps 4.4 to 4.12, or to make you an admin.
  • Later, replies fail with error code 200 or "Invalid OAuth access token". The system user may be missing access to the WhatsApp account. Meta says missing access gives error code 200. Check step 4.7.

Make up a verify token

1 min

When you save the webhook address in step 9, Meta sends a test request to check that the address really is yours. It does that by sending a word you chose. The app answers only if the word matches. Any long random string works.

  1. In Terminal, make a random string. 
    openssl rand -hex 24
    You should seeA line of 48 letters and digits, for example 9f2c.... It is different every time.
  2. Copy this

    Paste it into deploy/.env:

    WHATSAPP_VERIFY_TOKEN= followed by the string, no spaces, no quotes. Save the file.

    Meta does not give you this one. You will paste the same string into Meta in step 9. You can read it back at any time with grep WHATSAPP_VERIFY_TOKEN deploy/.env.

Start the app

5 to 10 min

The app runs in Docker. Run every command from the project folder, /Users/yasir/HARNYYS. If you opened a new Terminal window, run cd /Users/yasir/HARNYYS first.

  1. Check that Colima, the program that runs Docker on your Mac, is running. 
    colima status
    You should seeA line saying colima is running. If it says it is not running, start it with colima start.
  2. Check that Docker Compose works. 
    docker compose version
    You should seeA line such as Docker Compose version v2.... If you see unknown command: docker compose, do steps 7.3 and 7.4. That is what the Mac showed when I checked it on 25 November 2026. If it printed a version, skip to step 7.5.
  3. Install Compose. 
    brew install docker-compose
  4. Tell Docker where Homebrew put it. Open Docker's settings file. 
    open -e ~/.docker/config.json

    Add one line, "cliPluginsExtraDirs", and put a comma at the end of the line above it. Brew's own notes give this line. The file should end up like this:

    {
	"auths": {},
	"currentContext": "colima",
	"cliPluginsExtraDirs": ["/opt/homebrew/lib/docker/cli-plugins"]
}

    Save the file, then run docker compose version again. Your file may have other lines. Keep them. Only add the new one.

  5. Build and start everything. The first time takes several minutes, because Docker downloads the database and builds the app. 
    docker compose -f deploy/compose.yaml up -d --build
    You should seeLines ending in Started or Healthy, and then your prompt comes back.
  6. Check that the parts are running. 
    docker compose -f deploy/compose.yaml ps
    You should seeThree rows: postgres, server and worker. The server says healthy after 20 to 40 seconds. The one-off migration job is not listed. It finishes and exits, which is normal.
  7. Ask the app if it is well. 
    curl http://127.0.0.1:8000/api/health
    You should see{"status":"ok","database":"ok"}
  8. Optional but worth doing: try the app with no WhatsApp at all. This proves the model key works, so you know where to look if WhatsApp misbehaves later. 
    curl -X POST http://127.0.0.1:8000/api/webhooks/webchat \
  -H 'content-type: application/json' \
  -d '{"user_id":"demo-1","name":"Demo","text":"How much is the Ethiopia Yirgacheffe 250g?"}'

    Wait about 10 seconds, then read the conversation:

    curl http://127.0.0.1:8000/api/conversations/1/messages
    You should seeTwo messages: your question and a short answer from the app that names a price in AED. This uses sample products, marked (sample). The test makes conversation number 1, so your WhatsApp chat will probably be number 2.
If this goes wrong

Read the logs first:

docker compose -f deploy/compose.yaml logs --tail 60 server worker migrate
  • "Set POSTGRES_PASSWORD in deploy/.env". The password line is empty. Fill it in.
  • "Environment variable ... is not set" or the server stops at once. A line in .env is missing or empty. Run the check in step 6.4.
  • The server is not healthy. The log names the reason. If the migration job failed, the database password is the usual cause. The database remembers the first password it was given. If you must start again from nothing, docker compose -f deploy/compose.yaml down -v deletes the database, then run step 7.5 again.
  • Port 8000 is already in use. Another program is using it. Close it and run step 7.5 again.
  • The webchat test gives no answer. Check the worker log. Look for Turn 1 failed. The line above it names the reason. A wrong or empty MODEL_API_KEY, or an OpenRouter account with no credit, is the usual cause.
Whenever you change .env later

The app reads .env only when it starts. Restarting does not reload it. After any change to .env, run this instead:

docker compose -f deploy/compose.yaml up -d --force-recreate --no-deps server worker

The project's own README says docker compose -f deploy/compose.yaml up -d. The longer form makes sure the new values are picked up. I have not run either one on this Mac. not verified

Make the app reachable from the internet (test tunnel)

5 min

Meta must be able to reach your app. For testing, use a Cloudflare quick tunnel. It needs no account and no domain. It gives your Mac a random public address for as long as the command runs.

Read this before you start the tunnel

A quick tunnel exposes the whole app, not only the WhatsApp path. The app has no login yet. Anyone who learns the random address could read conversations. Use it for short tests, never share the address, and stop it with Ctrl + C when you are finished. Do not test with real customer data. The section "A permanent tunnel on our own domain", at the end, shows the safer setup.

  1. Install the tunnel program. Skip this if you did it before. 
    brew install cloudflared
    You should seeBrew finishes without an error line. cloudflared --version prints a version.
  2. Start the tunnel and leave this Terminal window open. 
    cloudflared tunnel --url http://127.0.0.1:8000
  3. Wait about 10 seconds and look through the text that appears.
    You should seeAn address that starts with https:// and ends with .trycloudflare.com, with random words in between.
  4. Copy this

    Copy that whole address. You need it in step 9. Add /api/webhooks/whatsapp to the end, so it looks like this:

    https://random-words.trycloudflare.com/api/webhooks/whatsapp

  5. Open a second Terminal tab with Cmd + T. In it, go to the project folder and test the address from outside. 
    cd /Users/yasir/HARNYYS
curl https://random-words.trycloudflare.com/api/health
    You should see{"status":"ok","database":"ok"}, the same answer as in step 7.
Good to know
  • The address changes every time you start the tunnel. After a restart, repeat step 9 with the new address.
  • The tunnel stops when you close that Terminal window, when you press Ctrl + C, or when the Mac sleeps.
  • Cloudflare says quick tunnels are for testing and have no uptime guarantee.
If this goes wrong
  • The curl says it could not resolve the host. A brand-new address can take a few seconds to work. Wait 30 seconds and try again.
  • You get an error page from Cloudflare, or a 502. The tunnel cannot reach the app. Run step 7.7 on your Mac. If that fails, the app is not running.
  • No address appears after a minute. Check your internet connection. Press Ctrl + C and start the tunnel again.

Connect the webhook in Meta

5 min

A webhook is how Meta tells your app that a customer wrote. You give Meta two things: the address to call, and the verify token from step 5. Meta then calls the address once to check it. After that, you tell Meta which kinds of events to send.

You need two values ready. Print the verify token like this, and copy the value after the = sign:

grep WHATSAPP_VERIFY_TOKEN deploy/.env
  1. In the Meta App Dashboard, open your app. In the left-hand menu click Use cases, then Customize next to the WhatsApp use case, then Configuration. label may differ
  2. Find the Webhook box with Callback URL and Verify token. If the boxes are locked, click Edit. label may differ
  3. In Callback URL, paste the address from step 8, ending with /api/webhooks/whatsapp.
  4. In Verify token, paste the verify token from step 5.
  5. Click Verify and save.
    You should seeThe box saves and a list of webhook fields appears. In Terminal you can confirm with docker compose -f deploy/compose.yaml logs --tail 5 server. The last lines include GET /api/webhooks/whatsapp followed by 200.
  6. In the list of fields, find messages and subscribe to it. Use the Subscribe button or the switch next to it. label may differ
    You should seeThe messages row switched on. Leave the other fields off. The app reads only messages.
  7. Do not click the Test link next to messages. It sends a made-up message. Use a real phone in step 10.
If Verify and save fails

The server log shows GET ... 404The address is wrong. The path must be exactly /api/webhooks/whatsapp.Fix the Callback URL.

Before the demo: the checklist

Day before

The test setup works today. These items stop it breaking on the day. Tick them off as you go.

App mode: Development or Live

New Meta apps start in Development mode. Meta's documents say some webhooks are not sent in Development mode, and that ready-made messages test webhooks work in both modes. So try Development mode first. Switch to Live only if real messages never reach the app.

  • The switch is in the App Dashboard top bar. Look for an App mode toggle. label may differ
  • Going Live may need a privacy policy URL, a public web page, in App settings, Basic. Meta's older announcement lists it. not verified Ask us for one before you try.
  • Meta warns that in Live mode only features approved through app review stay active, even for people with a role on the app. Do not switch for fun.

Optional, in parallel: a real number and business verification

The test number is enough for the demo. A real customer-facing number needs two more things from Meta: business verification, which proves your company is real, and a real phone number registered for WhatsApp. These can take days or weeks, so starting early is cheap. Look for business verification in Business settings, often under Security center. label may differ Meta's page on business phone numbers explains adding a real number. It also says the dashboard route alone does not finish the registration. A real number also needs a payment method. Ask us before you start, because it has more steps than this guide covers.

T

A permanent tunnel on our own domain

20 min

For the real demo, replace the quick tunnel with a named tunnel. It keeps the same address, runs in Docker next to the app, and exposes only the WhatsApp path. You need a domain whose DNS is managed by Cloudflare, and a Cloudflare account.

  1. In the Cloudflare dashboard, go to Networking, then Tunnels. Older dashboards call this Zero Trust, then Networks, then Tunnels. label may differ
  2. Click Create a tunnel. Choose Cloudflared if it asks for a type, give it a name such as yyai-whatsapp, and save it.
  3. On the next screen, Cloudflare shows an install command with a very long string in it. Pick the Docker tab if you see one. The token is that long string after --token.
    Copy this

    Paste the token into deploy/.env as CLOUDFLARE_TUNNEL_TOKEN= followed by the token. Do not run Cloudflare's install command. Our Docker setup does that for you.

  4. Open the tunnel's Routes tab. Click Add route, then Published application. Older dashboards call this a Public hostname. label may differ
  5. Fill in the route:
    • Subdomain: for example wa
    • Domain: pick our domain from the list
    • Path: /api/webhooks/whatsapp*
    • Service URL: http://server:8000
    Save it. Add no other route. Everything else stays private.
  6. Stop the quick tunnel. Press Ctrl + C in its Terminal window.
  7. Start the named tunnel from the project folder. 
    docker compose -f deploy/compose.yaml --profile tunnel up -d
    You should seeA cloudflared container started. In the Cloudflare dashboard, the tunnel shows Healthy.
  8. Check that only the webhook path is public. 
    curl -i https://wa.yourdomain.com/api/health
    You should seeAn error, not {"status":"ok",...}. That is the goal. Only /api/webhooks/whatsapp gets through.
  9. In Meta (the screen from steps 9.1 to 9.5), change the Callback URL to https://wa.yourdomain.com/api/webhooks/whatsapp with your real hostname. Keep the same verify token. Click Verify and save. messages stays subscribed.

If you added the token to .env after the app was already running, recreate the services as described at the end of step 7. The tunnel keeps its address across restarts, so you only do this once.

Words used in this guide

Access token
The key the app shows Meta each time it sends a reply. A temporary one, from the API Setup page, lasts a few hours. A permanent one comes from a system user (step 4). Goes in WHATSAPP_ACCESS_TOKEN.
App (Meta app)
A settings area on Meta's side that holds your WhatsApp test number, keys and webhook. Not something you install.
App Dashboard
The Meta web page where you manage your app.
App Secret
A password for your Meta app. Meta signs every webhook call with it. The app checks that signature. Goes in WHATSAPP_APP_SECRET.
Business portfolio
Meta's name for the company account that owns apps, WhatsApp accounts and phone numbers. It was once called Business Manager.
Callback URL
The public web address Meta calls when a customer writes. For us: https://<your-address>/api/webhooks/whatsapp.
Development mode and Live mode
The two states of a Meta app. New apps start in Development mode, where only people with a role on the app can use it. See step 11.
Graph API version
The version of Meta's web interface the app talks to. It is graph_version in config.yaml, now v23.0.
Messaging account / WABA
The account at Meta that holds your WhatsApp templates and billing. Meta's current documents say Messaging account. Older screens say WhatsApp Business Account, shortened to WABA. Same thing, same ID.
Phone number ID
A long number that identifies one WhatsApp number inside Meta. It is not the phone number itself. Goes in WHATSAPP_PHONE_NUMBER_ID.
System user
A robot account in Meta Business settings. It can hold a long-lived token that does not depend on your own login.
Test number
A free phone number that Meta makes for you when you set up WhatsApp in an app. It can only message phones you confirm on a list.
Tunnel
A service that gives a computer behind a router a public web address. We use Cloudflare. A quick tunnel is for tests and changes address each time. A named tunnel keeps its address.
Verify token
A word you make up. Meta sends it back when you save the webhook, and the app answers only if it matches. Goes in WHATSAPP_VERIFY_TOKEN.
Webhook
A web address that Meta calls to hand you something, here each new customer message. The opposite of asking Meta over and over whether anything is new.
24-hour window
Meta lets a business reply freely only within 24 hours of the customer's last message. After that, only pre-approved template messages are allowed.
